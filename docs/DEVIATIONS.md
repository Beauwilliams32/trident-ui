# Deviations from docs/SPEC.md

Every place the package differs from the spec, or fills a gap the spec leaves open. Newest first.

| Date | Area | Spec | What we did | Why |
|---|---|---|---|---|
| 2026-11-11 | Visual gate tolerance | §10.6: screenshots with maxDiffPixelRatio 0.1% | The tolerance is a ratio, so a small solid-colour change can fall under it at one width and over it at another. Swapping the Trident Ops accent moved about 500px: that is 0.11% of a 360px section (over the 0.1% limit, so the snapshot was rewritten) but 0.068% of the same section at 1280px (under it, so the snapshot **passed** and kept the old palette). The 1280px baselines were re-recorded with `--update-snapshots=all`, which writes unconditionally; the plain flag only rewrites what already fails | A colour change can therefore land in the baselines at one width and silently not at the other, and a later reader would see a green gate over a stale image. `--update-snapshots=all` is the correct command for an intended colour change, and the pixel count is worth reading before trusting a green visual gate. This also means the 0.1% ratio is not a reliable detector for small palette edits at wide widths; the contrast matrix (§9) is the gate for colour, the pixels are the gate for layout. |
| 2026-11-11 | Trident Ops theme | §3 themes; §1 bump rules | `themes.trident-ops` now carries the Ops brand rollout's own palette (bg #0c1a26, bg-2 / surface / surface-raised #0e242c, line #113738, line-strong #687688, ink #ffffff, ink-2 #d2d7e1, muted #9aa7bd, accent-1 #2fd39a, accent-2 #0f9f72, on-accent #0b0b0d, ok #2fd39a, warn #f5b83d, danger #ff6b5e, info #3ba8f0, r-lg 24px) as a full role override on the fleet base, replacing the two-role accent-only override that left the theme on the hub palette. Type stays the fleet's (Space Grotesk / Inter / JetBrains Mono) per §4; the rollout's Playfair Display display face is not adopted here | The package theme was out of step with the product's own brand rollout, so the live consumer (LocalOps) compensated with 19 handwritten `--ui-*` overrides in `styles.css` and rendered the rollout values anyway. The package now states them once: the 19 overrides become redundant and the rendered result is unchanged. Ops is the only package theme reconciled, because it is the only one with a live consumer; the other fleet themes keep their released values. All 29 §9 contrast pairs still pass, and no ratio falls below its floor. **Bump: major** (a Changesets `major`), because spec §1 and `.changeset/README.md` make any change to a colour role that appears in the §9 contrast matrix a major bump, and 31 §9 ratios change for this theme: ink, ink-2, muted, accent-text, on-accent, ok, warn, danger, info, focus and line-strong on bg, bg-2 and surface. The 2026-10-11 row's narrowing does not apply, because that change left every default role value untouched. The `quorum` re-sync in v0.2.0 was the same shape (27 roles, 31 ratios) and shipped as a minor while that release note claimed no contrast-matrix role changed value; that was an inconsistency, not a precedent to repeat. Nothing in the rendered output changes for the live consumer, so the owner may downgrade to `minor` at release if they judge the rule's purpose to be served. |
| 2026-11-11 | Gallery baselines | §10.6: every component × theme × reduced/pause × 360/1280 | 826 of the 840 baselines are re-recorded on macOS Chromium. The drift came from the 2026-11-10 mobile contract (`09132f4`): its new `game-control` gallery example and new tokens grew the `actions` and `tokens` sections by 249.50px and 143.75px, so every section below them moved by a **fractional** offset (`.125` → `.375`) and re-rasterised its text | The snapshots were stale, not wrong: the rendered DOM and computed styles of the affected sections are byte-identical to the recorded ones, and a control build of `d40015d` matches its own stored PNG at 0.000%, so the browser is deterministic and no font or OS drift is involved. 2026-10-20 set the precedent that a full re-record is the remedy when what sits above a snapshot changes; `805a9ee` re-recorded only the 56 `brand` baselines because `brand` sits last and moves no other snapshot. This row is the same remedy applied to the sections the mobile contract grew. The Trident Ops palette correction is re-recorded separately on top, so the two causes stay separable. |
| 2026-10-20 | Studio brand themes | §3: themes are the fleet, Williams Media, portfolio and Quorum sets | Two themes are added, `trident-ui` (dark) and `trident-ui-light`, on a new `studio` base in `tokens.json`: the Trident Studio brand system's colour, Playfair Display / Inter / JetBrains Mono, radius, motion and shadows mapped onto the existing role names (docs/BRAND.md). `bg-2`, `surface-raised`, `ink-2`, `line-strong`, `status-reasoning` and the four light signal inks have no brand equivalent and are derived, each passing the §9 matrix. The generator gains base-inherited `extra` and `elevation`; `extra` keys that name a global token (`dur`, `text-base`, `text-4xl`, `text-display`, `weight-display`) re-point it only while a studio theme is active | The brand ships one light and one dark set under `data-theme`; this package gives every theme one native scheme, so they are two themes. Existing themes are untouched (a new theme is a minor release). The brand's own layout numbers (1200px content width, 24px gutters) stay guidance: the `--ui-grid-*` tokens are unchanged so no existing page reflows. |
| 2026-10-20 | Playfair Display | §4 lists the self-hosted families | `@fontsource-variable/playfair-display@5.3.0` (OFL-1.1) joins the five families, synced by `npm run fonts:sync` with a Times New Roman metric fallback (112.04% size-adjust). Only the studio themes use it | The brand's display face. Self-hosted like the others: no Google Fonts connection, no new network dependency. The 2 woff2 files add about 59 kB to the package, not to any CSS or JS bundle. |
| 2026-10-20 | Gallery matrix | 2026-09-28 row: 12 themes × 2 motion × 2 widths = 48 pages, 576 baselines | 14 themes: 56 pages and 840 baselines (15 sections each; the count in the 2026-10-11 row already was 720) | The two studio themes are baselined in their native scheme like every other theme. All baselines were re-recorded on 2026-10-20: every snapshot is positioned by what sits above it, and the Brand section, the "What's new" text and a two-link longer theme switcher all changed. `brand` now sits last in the gallery so later changes to it move no other baseline. The gallery also prints the newest two CHANGELOG sections above every snapshot, so editing the Unreleased text there moves all 840: the 2026-10-20 lockups and link-preview card are recorded in the changeset until release, and only the 56 brand baselines were re-recorded for them. |
| 2026-10-11 | Increase Contrast | §9 contrast matrix; Apple HIG Increase Contrast | `tokens.json#high-contrast` generates per-theme `@media (prefers-contrast: more)` blocks (in `tokens.css` and each `themes/*.css`, after the palettes): ink, ink-2, muted and line-strong are mixed toward ink (ink toward white or black) in 1% steps until they meet 7, 8.5, 7 and 4.5:1 on bg, bg-2 and surface; line and glass-edge become the old line-strong; glass turns solid. Recorded as a minor change | No default colour role changes value; the overrides only apply to users who ask for more contrast, and only raise contrast. The changeset rule "contrast-affecting is major" was written for the default roles; the owner can still choose major at release. |
| 2026-10-11 | Touch targets | §9: 44px for primary actions on touch | Every interactive control gets an invisible 44x44 hit region under `(pointer: coarse)`. Three layout changes on touch only: text inputs grow from 40px to 44px (a hit region cannot be added to an `<input>` without one), fieldset options sit 20px apart, interactive chips take an 8px margin | Expanded regions must not overlap their neighbours or the extra area belongs to the wrong control (Material's touch-target wrapper does the same). Before any other visual change, all 48 desktop pages matched the old baselines (gate tolerance 0.1%), and at zero tolerance the only differing pixels (the paused Pause-motion button, one ±1 anti-aliased card corner) differ the same way on unchanged `main`. |
| 2026-10-11 | Menus are non-modal | Radix DropdownMenu and ContextMenu default to modal | `DropdownMenu` (prop `modal`, default false) and `ContextMenu` render non-modal | A modal Radix menu aria-hides the page while leaving it focusable, which axe reports as `aria-hidden-focus` (160 nodes). The WAI-ARIA menu-button pattern needs no modality; focus still moves in, Escape closes, focus returns. |

| 2026-10-02 | 3D chunk headroom | §6.6, §9: lazy 3D chunk ≤250KB gz | `src/three/generated.ts` reads a precomputed per-theme/per-palette int table (`src/three/generated-colors.json`, written by `scripts/build-tokens.mjs`, pinned to tokens.json by `units.test.ts`) instead of resolving all of tokens.json at runtime. Measured: macOS 248.92 kB -> 246.57 kB; CI 250.14 kB -> 248.03 kB (PR #4 run 36998047757) | CI's first run on `main` (run 36735914426) measured the chunk at **250.14 kB** and failed `npm run size`, while macOS measured 248.92 kB. Same bundle; the gzip differs: CI's official Node 24 build ships Chromium's zlib, Homebrew Node on this Mac links system zlib 1.2.12, and the CI figure is about 0.5% larger. Dropping the token prose, primitives and runtime resolver from the payload leaves about 2 kB of headroom on CI (3.4 kB on macOS) without touching the spec budget or the drei root-import rule. |
| 2026-09-30 | Install is a plain fetch | §1: "`dist/` is committed on the tag, and there is no `prepare` script, so an install is just a tarball fetch" | The library build script is `build:lib`, not `build`, and `test/package.test.ts` bans every script name npm prepares on (`prepare`, `prepack`, `build`, `install`, `preinstall`, `postinstall`) plus `workspaces`. `v0.1.0` was cut with a `build` script and is not installable; `v0.1.1` is the first consumable tag | Having no `prepare` script is not enough: npm's git fetcher (pacote `lib/git.js`) also prepares on `build`. Found by the v0.1.0 consumer-install proof. |
